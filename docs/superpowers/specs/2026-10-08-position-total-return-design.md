# 120 日位置指标：复权口径确认与文案修订 设计文档

> 日期：2026-10-08 | 状态：待审批

## 概述

一次针对选股策略一致性的对抗性复核发现：**「120 日位置」用前复权（全收益）K 线计算，而波动率、最大回撤、股息率历史分位用不复权（价格）K 线**——而位置的复权选择**在代码注释与三份文档里都没有任何说明**。同时暴露两个表面问题：

1. 文案把窗口写死为「120日」，但窗口其实来自配置项 `rules.yaml` 的 `data.kline_days`（README 自己写的是「近 `kline_days` 根（默认 120 根）」）。用户把 `kline_days` 改成 60，报告仍印「120日高位」。
2. 文案未声明口径。「120日高位」读起来像在说**行情软件上那张价格图**，实际算的是**全收益图**。

复核实测的量级足以让它值得处理：位置（前复权）− 位置（不复权）在 132 只候选股上**平均 +6.7pp、中位 +3.8pp、最大 +39.1pp**（江阴银行 84.5 vs 45.4、格力电器 60.5 vs 25.4），**25 只（19%）的高/中/低分类随之翻转**，前复权路径判 40 只高位、不复权只判 28 只。

本次**不改变计算口径**——复核后确认前复权是正确的选择（见决策 1），要把缺失的**记录**补上，并把文案改成不再误导。

**约束**：零分数变化、零买入名单变化。本次只改文案与文档，不动任何取数与判定逻辑。

---

## 关键口径决策

1. **位置用前复权（全收益）口径，这是正确的，不统一到不复权。** 位置要回答的是「现在买入是否追高」——而对分红投资者，**除息不是损失**，钱以分红形式拿到了。用价格图会把「刚除息」误判为下跌，把高分红股系统性算成低位（那反而会制造买入信号）。该口径同时与最大回撤的「含分红总回报口径」（`rules.yaml` 注释、CLAUDE.md）一致：两个价格类指标都按持有人实际收益算。
2. **与波动率/最大回撤/股息率分位的「不复权」取数不同，是有意的，不是待统一的疏漏。** 那三处各有理由，且其中一处是**必须**：
   - **股息率历史分位必须用不复权**——前复权价已扣除后来的分红，会把历史股息率系统性算低（`src/indicators.py` 的 `calc_dividend_yield_percentile` 已文档化此理由）。
   - **波动率与最大回撤用不复权**——复核实测：把分红加回同日价格重算 250 根波动率，差异**均值仅 +0.31pp、中位 +0.18pp**，132 只里只有 3 只档位变化。README 的「除息噪声可忽略」结论成立。不值得为此改动取数。
   
   因此本决策的结论是：**保留三处不复权、位置保留前复权，把这个分工写进文档**，而不是强行统一。
3. **文案行内声明口径，窗口取自配置。** 格式 `{window}日全收益低位/高位/中位 X%`。行内声明而非集中说明，是因为位置短语是**表格里的一列文字**（低位并入亮点列、高位并入风险列），读者往往会单独复制或截取某一行来看，脱离报告的上下文；「全收益」三字是理解这个数字含义的最小充分信息。**注**：位置短语只出现在报表的两个列里——交互式详情页（`render_detail`）不渲染它（它只输出指标表、扣分链与覆盖行），故本次不涉及详情页。
4. **不改 `POSITION_LOW`/`POSITION_HIGH`（30/70）阈值，不改 `_signals` 的判定结构。** 阈值与「高位剥夺买入资格」的取舍属策略意图范畴，另案处理。

## 模块详细设计

### `src/reporter.py`

**`_position_phrases(position)` → `_position_phrases(position, window: int = 120)`**（约 493 行）

`window` 给默认值是有意的：`_position_phrases` 共有两个调用点，其中 `_signals`（约 98 行）只用它做高位判定、不渲染文案，窗口值对它无意义，故无需改动。

文案改为：

| 分支 | 现文案 | 新文案 |
|---|---|---|
| `value <= POSITION_LOW` | `120日低位 23%` | `{window}日全收益低位 23%` |
| `value >= POSITION_HIGH` | `120日高位 82%` | `{window}日全收益高位 82%` |
| 中间档 | `120日中位 55%` | `{window}日全收益中位 55%` |
| 无法转 `float`（`None`、字符串等） | `(None, None)` | `(None, None)`（不变） |

**硬约束：返回值结构 `(low_phrase, high_phrase)` 必须保持不变。** `reporter.py:98` 的 `_signals` 用 `_position_phrases(item.get("position"))[1] is not None` 判断是否高位——这是「高位剥夺买入资格」规则的实现基础，改文案不得动结构。

`window` 应为 `int`；非法值（非 int、`bool`、≤0）按 `120` 兜底，不抛异常。排除 `bool` 的理由与 `src/config.py` 校验权重时一致——Python 里 `True` 是 `int` 的实例，不排除会让 `position_window=True` 静默渲染成「1日」。

**`render_report(...)`** 新增关键字参数 `position_window: int = 120`，传给它表格循环里的那个 `_position_phrases` 调用（约 189 行，一次调用同时解包低/高两个短语）。默认值 120 保证既有调用方与既有测试不受影响。

### `main.py`

`run_scan` 调 `reporter.render_report(...)` 处传入 `position_window=cfg.rules["data"]["kline_days"]`。这是唯一的配置来源，不在 reporter 内读配置（reporter 至今不依赖配置加载，保持这一点）。

### 文档三处

1. **`docs/superpowers/plans/2026-10-06-dividend-screener.md` 的「关键口径决策」** 追加第 5 条——该节是项目记录口径决策的地方，CLAUDE.md 指名「改动打分/口径前先读它」。内容：位置的复权口径 = 前复权（全收益），理由同本 spec 决策 1；并列出四个价格类指标各自的口径与理由。

3. **`README.md` 的「输出说明」**：位置短语的示例文案更新为新格式，并说明全收益口径。

## 测试策略

遵循项目约定：**测试绝不联网**，reporter 测试全部用内联 result dict 构造，不依赖 akshare 与配置加载；一律用 `.venv/bin/pytest`。

- 文案三分支（低/中/高）各自断言新格式与数值。
- 窗口来自参数：`position_window=60` → `60日`；缺省 → `120日`。
- 非法窗口兜底。
- **回归守卫**：断言 `_position_phrases` 返回值仍为二元 tuple 且高位分支的第二个元素非 None——`_signals` 的正确性依赖它，改文案时最容易被破坏的就是这里。
- 全量 `.venv/bin/pytest` 必须全绿；收尾跑一次 `main.py --no-interactive` 目视确认风险列文案。

## 不纳入范围

- **`payout_ratio` 的两档问题**（`_range` 只返回 1.0/0.0，与项目「关键口径决策 #4：档位统一三档」不符；且区间外一律 0 使支付率 10% 与 90% 同分）。复核已确认这是真问题，但它需要设计「第三档表示什么」——属独立的打分口径设计，另案处理。
- **位置阈值（30/70）与「高位剥夺买入资格」规则本身。** 复核实测该规则在候选池上几乎等价于「银行不买入」（前 20 名中 9 只银行有 7 只被剥掉资格）。是否保留、阈值是否该调，属策略意图选择，另案处理。
- **统一四个价格类指标的复权口径。** 决策 2 已裁定保留现状并记录理由。
- **股息率被两个指标重复计入**（`dividend_yield` 15 分 + `dividend_yield_percentile` 10 分，样本内 r = 0.44）、**支付率与 `cash_cover` 重复扣分**（7 只同时触发）。均为独立的因子设计问题，另案处理。
- **`NaN` 位置的既有瑕疵**：`float('nan')` 能通过 `_position_phrases` 的类型转换，却不满足任何一个比较分支，于是落到中间档、渲染成「中位 nan%」。**数据层不可达**（`calc_position` 只返回 `None` 或 0–100 的有限值），且本 spec 的约束是「零行为变化」，故本次不处理——特此记录，免得日后被当成新引入的问题。
