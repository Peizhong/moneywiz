# 分红筛选器（Dividend Screener）

一款基于 Python 的命令行投资辅助工具：维护自选股票列表，运行后自动拉取
行情、分红、估值数据（数据源 [akshare](https://akshare.akfamily.xyz/)，免费、无需注册），
按红利策略多因子加权打分，在终端输出按总分降序排列的股票表和摘要。

## 环境安装

需要 Python 3.12+：

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt        # 运行依赖
.venv/bin/pip install -r requirements-dev.txt    # 开发依赖（pytest）
```

## 配置文件

四个 YAML 都在 `config/` 下，缺失或格式/字段不合法会在启动时报错并指出具体文件：

### `config/stocks.yaml` — 自选股票

```yaml
stocks:
  - code: "000001"    # 6 位代码，字符串
    name: "平安银行"
```

### `config/holdings.yaml` — 持仓

```yaml
holdings:
  - code: '600036'   # 股票代码
    cost: 32.50      # 每股成本（元）
```

持仓股在运行时并入扫描清单，与其他股票**按代码去重**后统一评估（自选名优先；
纯持仓股名称取自行情表）。持仓与自选同待遇：**不参与 `candidate_top_n` 裁剪、不占
名额**。**成本价原样使用**——分红摊薄、加减仓后的成本由你手动维护，工具不自动调整。
浮亏达到 `risk_hints.holding_loss`（默认 -10%）时，报告风险列提示「持仓浮亏 X%」；
只标注、不参与打分。

### `config/dividend_index.yaml` — 红利指数成分股（自动维护，可多指数）

```yaml
indices:
  - index_code: "000015"             # 上证红利指数（510880 跟踪）
    index_name: "上证红利"
    updated_at: "2026-10-06T12:00:00"  # 该指数最近一次刷新时间
    constituents:
      - code: "600015"
        name: "华夏银行"
      - code: "601088"
        name: "中国神华"
        added: "2026-10-06"          # 可选：本次刷新新加入的成分股会带该字段
  - index_code: "931468"             # 红利质量
    index_name: "红利质量"
    updated_at: "2026-10-06T12:00:00"
    constituents: [...]
```

每个指数的 `updated_at` 各自独立：超过 `index_refresh_days`（rules.yaml，默认
14 天）时，运行会自动向中证指数官网刷新该指数——新增成分股写入 `added` 字段并在
当次报告的股票名后标注 `(新增)`，被调出的个股从文件中移除（日志按指数列出新增/
调出）。某指数刷新失败时沿用其现有名单并告警，不影响其他指数与整体运行。运行时
扫描 **自选 ∪ 各指数成分股**（按代码去重，自选优先）。成分股会先按**总市值取前
`candidate_top_n`**（rules.yaml，默认 80）再进入逐股取数：自选不参与筛选也不占名额；
取不到市值的成分股直接剔除并在日志里列出代码；行情整表不可用（东财与腾讯都失败）
时本轮不筛、按全量扫描并告警。注意：只支持 A 股指数
（港股指数与宽基不在工具的数据链路覆盖内；指数越多，冷启动耗时越长，日频档缓存
命中后不受影响）。

### `config/rules.yaml` — 权重与阈值

- `stocks.indicators`：每个指标的 `weight`（总和必须为 100）
  与阈值档位；指标值按阈值分为 1.0 / 0.5 / 0.0 三档；
- `data`：`kline_days`（K 线窗口天数，默认 120）、`pe_cache_days`
  （行业 PE/PB 缓存有效期，默认 7 天）、`financial_cache_days`（年报可持续性数据
  缓存天数，默认 30 天，财报季度更新）、`index_refresh_days`（成分股自动刷新
  阈值，默认 14 天）、`candidate_top_n`（成分股合并去重后
  按总市值取前 N，默认 0 = 不筛；候选越多冷启动越慢，裁剪只影响逐股取数的只数）；

  取数缓存分三档，各自独立（某一档设 0 = 该档每次运行都取最新）：

  | 键 | 默认 | 覆盖的取数 | 变化频率 |
  |---|---|---|---|
  | `quote_cache_minutes` | 0（不缓存） | 行情 | 随分钟变，是股息率的分母 |
  | `daily_cache_hours` | 6 | K 线、指数 PE、指数股息率、10Y 国债 | 每个交易日一次 |
  | `slow_cache_days` | 7 | 分红明细 | 分红一年实施 1~2 次 |
- `output`：`buy_top_n`（前 N 名标「买入」）、`avoid_bottom_n`（末尾 N 名标「末位」）。

## 运行

```bash
.venv/bin/python main.py     # 或先激活 venv，再执行 python main.py
```

在项目根目录执行；配置与缓存分别读写 `config/` 与 `cache/`（行业 PE/PB 缓存
`cache/pe_cache.json`，过期为 `pe_cache_days` 天；年报可持续性缓存
`cache/financial_cache.json`，过期为 `financial_cache_days` 天；行情/分红等
取数统一缓存在 `cache/market_cache.db`（SQLite），按上表三档各自计时）。
行情默认不缓存——每次运行都重新取，保证股息率用的是当前价格；
日频与慢变档在 TTL 内重复运行不再请求上游，因此间隔内的重复运行只需 1-2 秒。
东财行情（push2 系列）调用失败会
熔断 30 分钟并持久化在同一个缓存库：期间直接使用腾讯回退源或按数据不足处理，
避免每次运行都为被拒的接口重复等待。
配置错误时打印错误并返回退出码 1，
正常结束返回 0。

### 报表后的交互式详情

在交互式终端里，报表打印完不会立即退出，而是进入选择列表：输入代码或名称即筛选，
回车查看该股详情——逐指标的数值/档位/权重/贡献、加权小计 → 可持续性扣分 → 总分、
缺失指标；**按任意键**回到列表继续选，Ctrl-C 直接退出。

```
? 选择要查看详情的股票 ↑↓ 选择 · 输入即筛选 · 回车查看 · Ctrl-C/Ctrl-Q 退出
 » 20(并列4)  600036 招商银行  75.0  观察

600036 招商银行   总分 75.0   排名 20(并列4)   信号 观察
指标          数值    档位    权重    贡献
----------  ------  ------  ------  ------
股息率        4.9%     1.0      15    15.0
股息率分位     31%     0.0      10     0.0
连续分红      24年     1.0      15    15.0
...
加权小计 75.0 → 可持续性扣分 0% → 总分 75.0
缺失指标：无（覆盖 9/9）
 读完按任意键返回列表 · Ctrl-C 退出
```

（详情之后会停下等一次按键——列表有几十行，立刻重绘会把详情顶出屏幕。）

- 详情只用本次运行**已经算好的数据**（`values` + 规则重算档位），不额外请求上游；
  各指标「贡献」之和恒等于「加权小计」，也就是扣分前的总分。
- 输出被重定向或走管道时（`> report.txt`、Docker、CI）**自动跳过**交互，绝不阻塞；
  想显式关闭用 `python main.py --no-interactive`。
- 依赖 [questionary](https://github.com/tmbo/questionary)（已在 `requirements.txt`）。

### Docker

```bash
docker build -t moneywiz .
docker run --rm moneywiz           # 直接运行筛选，无需任何挂载
docker run --rm moneywiz pytest    # 容器内跑测试
```

构建时把本机的 `config/`（自选、规则、成分股）与 `cache/`（行情/财报缓存）
一并打进镜像，**不需要挂载**——改了自选/规则后重新 `docker build` 即可。
镜像内的缓存是构建时的快照：各档 TTL 到期后容器会自动重新拉取（行情本就不缓存，
容器内每次运行都会重新取；非交易时段拿到的仍是最近一个收盘价）；容器内
新增的缓存随 `--rm` 消失，需要跨运行保留时自行挂 `-v` 或改用 `docker commit`。
容器以非 root（uid 1000）运行；时区默认 `Asia/Shanghai`，可用 `-e TZ=...` 覆盖。
容器默认没有 TTY，交互式详情会自动跳过；想要详情用 `docker run -it --rm moneywiz`。

## 快照与历史分析

`snapshot.py` 是快照入口：跑一遍筛选并把结果写成 `snapshots/YYYY-MM-DD.{json,txt}`
两份快照（结构化榜单/指标 JSON + 与 main 相同的报告文本）。**同一天重复运行覆盖
同名文件**（只保留最后一次），历史快照全部保留、不自动清理；`snapshots/` 随
代码仓库跟踪。

在 Claude Code 里输入 `/moneywiz`（skill 定义见 `.claude/skills/moneywiz/`）：
skill 会运行快照脚本，然后对比历史快照（默认参照昨日、约 7 天前、约 30 天前）
分析买入区进出、信号与总分变化、板块温度计趋势，输出中文变化分析。
数值对比一律以 JSON 为准，txt 仅供人读。

```
【板块温度计】中证红利股息率 4.14%，10Y国债 1.82%，利差 +2.32pct，上证红利PE分位 14%
【股票】
  排名    代码  名称        总分  覆盖    信号    亮点                              风险                       技术
------  ------  --------  ------  ------  ------  --------------------------------  -------------------------  ----------------
     1  000001  平安银行    92.5  9/9     买入    股息率 5.9%、连续分红 24年        -                          MACD 金叉 RSI 56
     2  300750  宁德时代    58.3  3/9     观察    股息率 3.1%、120日全收益中位 44%  连续分红 2年               RSI 42
     3  600036  招商银行    25.0  9/9     末位    120日全收益低位 18%               连续分红 2年、PB估值 +35%  RSI 42
扫描 3 只股票，数据不足 0，指标不全 1，耗时 12.3s
```

（示例使用 `output: {buy_top_n: 1, avoid_bottom_n: 1}`。）

- **板块温度计**（报告首行）：中证红利指数股息率（中证指数官网）、10 年期国债收益率
  （近 90 天窗口）、两者利差（pct），以及上证红利 PE 历史分位（乐咕乐股，全历史区间
  近似分位）。用于判断红利资产的相对配置价值；任一字段取不到时跳过该字段，全部取不到
  时不显示该行。
- **总分**：各指标按阈值分档（1.0 / 0.5 / 0.0）后按权重加权，满分 100；只对能拿到
  数据的指标重新归一化。这意味着个别指标缺失不会直接拉低分数，但反过来，高分也可能
  只由少数几个指标支撑——请同时看「覆盖」列，覆盖低的分数代表性有限。全部指标都
  拿不到数据时显示 `N/A`，信号为「数据不足」。
- **覆盖**：该标的已评分指标数 / 应有指标总数（如 `9/9`、`3/9`；一个指标都没评到
  时如 `0/9`）。覆盖不全时分数只反映已评分的那部分指标。
- **信号**：按表内排名给出 —— 前 `buy_top_n` 名「买入」，但**处于高位（分位 ≥70%，
  窗口取自 `kline_days`）的标的不标「买入」**：名额按名次顺延给后面的非高位标的，递补按
  同分组整体补入（不按代码顺序切开同分；组内其余高位成员仍单独除外）。末尾
  `avoid_bottom_n` 名「末位」（不受位置影响）、其余「观察」，被高位剥夺买入资格
  的标的落为「观察」；无分标的固定为「数据不足」，不占用买入/末位名额。
  同分标的共享名次（竞赛排名，显示为 `1(并列6)`），边界上的同分不会被代码排序切开；
  「买入/末位」都是**表内相对**标签，不代表绝对买卖建议。
- **名称标记 `(新增)`**：该股在近 `index_refresh_days` 天内新加入红利指数成分股
  （对应 `dividend_index.yaml` 里的 `added` 字段），仅在刷新后的一段时间内标注。
- **分红可持续性（并入风险列 + 总分扣分）**：四个维度各自判定、维度内只取最重一条，
  文案由 `scorer.evaluate_sustainability` 的触发明细渲染（**展示层不重判阈值**）。
  **利润**：净利润增长率按**最新报告期**（年报/中报/季报的累计同比口径）检查，< 0 提示
  「盈利下滑 X%（2026中报）」并标注报告期——只看年报会漏掉"年报仍增长、中报已转负"的
  分红陷阱；近 4 期中 ≥3 期为负提示「盈利连续下滑 3/4 期」。**现金流**：最近年报每股
  经营性现金流 ≤ 0 提示「经营现金流为负」；**同季同比**单期下滑提示「现金流下滑 X%」、
  近 4 期中 ≥3 期为负提示「现金流连续下滑 3/4 期」——现金流绝对水平与分红覆盖率固定按
  最近年报口径（半年现金流与 TTM 分红不可比）。**覆盖**：近 12 个月每股分红 ÷ 每股
  经营性现金流 > 100% 提示「分红超现金流 X%」。**负债**：资产负债率**同季同比**上升
  ≥10pp 提示「负债率上升 Xpp」；利息支付倍数为**正**且 < 2 倍提示「利息保障 X 倍」
  （负值/零表示利息净收入为正，属财务健康，不提示；不用负债率绝对水平——绝对阈值会
  永久误报银行，实测四大行 90%+）。
  红标同时**扣总分**：利润 -5（单期下滑）/-15（连续恶化）、现金流 -15（为负）/-5
  （单期下滑）/-15（连续恶化）、覆盖 -10、负债 -10，维度内只取最重一条，合计**封顶
  -45%**（在 `rules.yaml` 的 `stocks.sustainability` 可调），避免"掏空式分红"拿高分。
  财报数据源为新浪财经（按 `financial_cache_days` 缓存），获取失败时无此项。
- **波动率（参与打分，权重 15，越低越好）**：近 250 根（约 1 年）日线的年化波动率，
  ≤`low`（默认 20%）/ ＜`mid`（默认 30%）对应 1.0 / 0.5，更高 0。取**不复权**K 线
  （与股息率历史分位共用同一次取数）；除息造成的单日下跌对 250 根窗口的波动率影响
  可忽略。满分档并入亮点（如「波动率 13.3%」）、零分档并入风险（如「波动率 41.1%」）。
- **最大回撤（参与打分，权重 5，越低越好）**：近 250 日峰值到谷底的最大回撤，按
  **总回报口径**（已实施分红加回除权除息日价格，避免高股息标的被除息日的价格下跌
  虚增回撤），≤`low`（默认 15%）/ ＜`mid`（默认 25%）对应 1.0 / 0.5。满分档并入
  亮点（如「最大回撤 10.4%」）、零分档并入风险。
- **流动性提示（并入风险列，只标注）**：近 60 日均成交额 < `turnover_low`
  （默认 5000 万）提示「日均成交 X万/亿」。阈值在 `rules.yaml` 的 `stocks.risk_hints`
  可调；波动率自成为打分指标后不再单独提示（零分档已在风险列显示）。
- **持仓标记与浮亏提示（只标注，不影响分数）**：持仓股名称后标注 `(持仓)`；
  现价较成本浮亏达到 `stocks.risk_hints.holding_loss`（默认 -10%）时风险列提示
  「持仓浮亏 X%」。成本价在 `config/holdings.yaml` 维护，工具不自动调整。
- **分红趋势（参与打分，权重 10）**：近 3 个年度 vs 前 3 个年度每股分红变化率，
  ≥0 / ≥-30% / 更差 对应 1.0 / 0.5 / 0；前 3 年无分红但近 3 年有 → 视为增长。
- **股息率历史分位（参与打分，权重 10）**：当前 TTM 股息率在该股近 3 年（约 790 个
  交易日）逐日重算的股息率序列中的分位，≥70% / ≥40% / 更低 对应 1.0 / 0.5 / 0。
  历史股息率用**不复权**收盘价计算（前复权价已扣除后来的分红，会把历史股息率系统
  性算低）。用于区分"股息率高"是绝对水平还是相对自身历史——例如大行股价上行后
  股息率分位降到个位数，说明是在为增长支付高价。K 线不足 250 根或窗口内无分红时
  该指标不可评分。
- **亮点 / 风险**：满分档（1.0）与零分档（0.0）的指标「名称 + 数值」（单位随指标，
  如 `股息率 5.9%`、`PE估值 +35%`），各最多两项；无则显示 `-`。
- **位置（并入亮点/风险文字）**：最新收盘价在近 `kline_days` 根（默认 120 根，约半年）
  K 线 [最低, 最高] 区间中的分位；窗口数取自 `kline_days`，改配置文案随之变。≤30% 视为
  低位（并入亮点），≥70% 视为高位（并入风险，且不标「买入」，见上），30%–70% 以中性
  文字并入亮点；无 K 线数据时不显示。文案里的**口径词固定**：
  - **股票**「`{kline_days}日全收益低/中/高位 X%`」——取数用**前复权** K 线，除息不是
    损失（钱以分红形式拿到），且与最大回撤的含分红总回报口径一致。这与波动率、最大
    回撤、股息率历史分位所用的**不复权**帧不同，**是有意的**（那三处各有理由，见 plan
    的「关键口径决策」第 5 条）；文案显式声明「全收益」以免被当成行情软件上的价格图。
- **技术**：股票的 MACD 信号（金叉/死叉）与 RSI 数值，仅作参考，不参与打分。
- **摘要行**：扫描股票数、数据不足数（完全无法评分的标的数）、指标不全数
  （已评分但有部分指标缺失的标的数）、耗时。

## 已知限制

- **数据源回退（东财 → 腾讯/新浪）**：`push2*.eastmoney.com` 可能按出口 IP 拒绝
  请求（海外实测 TLS 握手成功即被断开）。东财失败时自动回退：
  - 个股行情与 K 线 → 腾讯（`qt.gtimg.cn` 批量行情、`web.ifzq.gtimg.cn` 前复权日线）；
    K 线腾讯失败（如 HTTP 501 限流）→ 新浪 `stock_zh_a_daily`（前复权/不复权），

  最多 `pe_cache_days` 天，指数 PE 分位取历史区间近似分位，均非投资建议。
